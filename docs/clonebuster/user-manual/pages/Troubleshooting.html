Troubleshooting

The banners, Console messages and export results CloneBuster shows, and what to do about them.

Exporter banners

BannerCauseWhat to do
Your project is now timestamped.The first open after the import.Commit CloneBuster Vault, then select Got it.
N files can't be shown in a reel or a PDFFiles saved without the image CloneBuster reads.Select Show: one file is selected in the tree with its fix, several are listed with theirs. Refer to Fix a file saved without its image.
Timestamps are waiting for the network.The timestamp authority couldn't be reached.Nothing: versions are still recorded, and are sent once the connection returns.
The timestamp authority refused the last request.The authority answered without a token.Check the Timestamp authority address in the settings.
OpenTimestamps needs curl, which this system lacks.The curl command isn't installed.Install curl. RFC 3161 timestamps continue meanwhile.
The vault can't be writtenThe disk is full, or CloneBuster Vault is read-only or locked.Fix the cause the banner names. Recording resumes on its own.
... has been busy for over a minute, so it isn't recorded yetAnother program has kept the named file locked, or rewritten it, for over a minute. The rest of the vault keeps recording.Close the program holding the file, or let it finish writing. CloneBuster records the file once the program lets go of it.
CloneBuster is turned offEnabled is disabled in the settings.Select Settings to enable it.

Export results

ResultMeaning
Nothing exported: no ticked version has its RFC 3161 timestamp yetEvery ticked version was recorded offline. Export again once the network returns.
The Bitcoin proof for N versions isn't confirmed yetThe export leaves it out. Export again in a few hours to add it. Refer to Export again once Bitcoin confirms.
N versions left out: their RFC 3161 timestamps aren't in yetThe versions were recorded offline. Export again once the network returns.
N versions' originals weren't found on disk or in git historyThe message names the files and versions. Each file has changed since, and git doesn't have those versions: git isn't installed, the file isn't tracked, or the versions are older than its last 300 commits. Their previews and proofs still date them.

Fix a file saved without its image

Some tools save files without the flattened image CloneBuster reads. When that happens, the version is still hashed and timestamped, but it has no preview, so it can't appear in a reel or as an image in a PDF. The Exporter shows a banner, and the Console window shows the fix.

FileFix
A PSD file without a composite imageIn Photoshop, go to Preferences > File Handling, set Maximize PSD and PSB File Compatibility to Always, then save the file again.
A .blend file without a thumbnailIn Blender, go to Preferences > Save & Load, enable Save Preview Images, then save the file again.
A compressed .blend fileIn Blender's Save As window, disable Compress, then save the file again.
A .procreate file without a thumbnailSave the file again from Procreate.
A file shown as Unreadable, such as a 16-bit, CMYK or PSB fileSave it as an 8-bit RGB or grayscale PSD, or again from its own tool.

Fix the setting as soon as you see the banner: a version that was saved without its image can't get a preview later.
