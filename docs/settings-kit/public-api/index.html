SettingsPage

abstract class

Declares a settings page. Inherit it once, then attach entries through a SettingsEntry<TPage> base. The page appears in Project Settings, in Preferences, or both, depending on the kinds of entries attached to it, each window listing only its own entries. Its tree label and ordering come from an optional SettingsDisplayAttribute.

Abstract Members
abstract string Path { get; } The page location in the settings tree, where / nests under a parent (for example "My Game" or "My Game/Networking"). Read once per editor session and cached, so it must be constant.
Virtual Members
Both are read each time the page is drawn, so they may be computed.
virtual string Description { get; } An optional help box drawn at the top of the page. Defaults to null (none).
virtual string HelpUrl { get; } An optional documentation URL. When set, a "?" button linking to it is drawn on the page. Defaults to null.

SettingsEntry

abstract class

The non-generic root of every settings entry. Its constructor is inaccessible outside Settings Kit, so you never inherit it directly. Inherit one of the four generic bases below, which bind an entry to a page. The stored container holds a List<SettingsEntry>; this type has no public members.

SettingsEntry<TPage>

abstract class

The base for a shared build setting: committed, shipped into builds, and readable at runtime through Settings<T>.Instance, with the same value on every platform. The concrete type must be [System.Serializable] with a parameterless constructor; its field initializers and that constructor set the defaults. TPage is constrained to SettingsPage, new().

Constructor
protected SettingsEntry() Inherited by a concrete entry; not called directly.

PlatformSettingsEntry<TPage>

abstract class

The base for a per-platform build setting: like SettingsEntry<TPage>, but the whole entry can hold different values per build target. Settings<T>.Instance returns the instance resolved for the running platform; a player carries only its own platform's baked values. TPage is constrained to SettingsPage, new().

Constructor
protected PlatformSettingsEntry() Inherited by a concrete entry; not called directly.

EditorSettingsEntry<TPage>

abstract class

The base for an editor-project setting: committed to version control but never shipped into a build, so in a player Settings<T>.Instance returns the type defaults. TPage is constrained to SettingsPage, new().

Constructor
protected EditorSettingsEntry() Inherited by a concrete entry; not called directly.

UserSettingsEntry<TPage>

abstract class

The base for a per-developer setting: local and shown in the Preferences window. Its value is not shipped, so in a player Settings<T>.Instance returns the type defaults. TPage is constrained to SettingsPage, new().

Constructor
protected UserSettingsEntry() Inherited by a concrete entry; not called directly.

SettingsDisplayAttribute

Attribute

Optional display metadata for a page or an entry: the title (a page's tree label or an entry's section header), a tooltip, and the ordering among siblings. Omit it and the title defaults to the last segment of the page path, or the nicified entry type name (AudioDefaults becomes "Audio Defaults"). Applies to a class, not inherited, single use.

Constructors
SettingsDisplayAttribute() Declares display metadata, leaving the title to its default.
SettingsDisplayAttribute(string title) Declares display metadata with an explicit title.
Properties
string Title { get; set; } The title shown in the settings window: a page's tree label, or an entry's section header.
string Tooltip { get; set; } An optional tooltip for the title.
int Order { get; set; } The ordering among sibling pages or sections, lower first.

Settings

static class

Settings Kit's load state, editor saving, page navigation, and test seam. Read settings values through Settings<T>.Instance.

Properties
static bool Loaded { get; } Whether the configured settings are available. Always true in the editor; in a player, true once the shipped settings finish loading (before the first scene). While false, a read answers with defaults, so treat false as retry-later.
Methods
Reads go through Settings<T>.Instance.
static void Save() Persists changes made to a settings entry from editor code. [Conditional("UNITY_EDITOR")]: the call is stripped from a build, so it is always safe to call.
static void OpenPage<TPage>() where TPage : SettingsPage, new() Focuses the page of TPage in its settings window (Project Settings or Preferences). [Conditional("UNITY_EDITOR")]: stripped from a build.
static IDisposable OverrideForTests<T>(T value) where T : SettingsEntry, new() Substitutes what Settings<T>.Instance returns for T until the returned handle is disposed, so a consumer can unit-test code that reads settings without touching the stored file. The substitution reverts on dispose. Throws ArgumentNullException when value is null.

Settings<T>

static class

A cached read of a single entry, and the way to read a setting. Settings<T>.Instance returns the configured instance of T (a default one if it was never configured, and the variant resolved for the running platform for a per-platform entry). A built player resolves it once and then serves it from a field, so a read is a plain field access with no lookup; the editor and test builds re-resolve on every read, so it stays live with settings-window edits and honors Settings.OverrideForTests. Reading through it means consuming code never has to cache the value itself. Safe to read off the main thread once settings have loaded. T is constrained to SettingsEntry, new().

Properties
static T Instance { get; } The project instance of T, or a default one if it was never configured. Treat the result as read-only: runtime changes are not persisted. Prefer this over caching the value in your own field: a private cache is bypassed by OverrideForTests and goes stale when the resolved instance is replaced (a revert or undo in the editor, or a build-target change for a per-platform entry), while Instance is already a raw field read in a shipping build.

IValidatedSettings

interface

Opt-in on a settings entry to validate it in the inspector, and at build time for build settings. One hook, two uses: an inline help box under the section, and a build gate that throws a BuildFailedException on failure.

Methods
bool Validate(out string error) Returns whether the entry is valid; on false, sets error to a message shown in the settings window and, for a build setting, fails the build.

IVersionedSettings

interface

Opt-in on a settings entry to transform its already-deserialized fields forward across schema versions, for value changes that Unity's field-rename and type-move attributes cannot express. Editor-only; runs once when the settings load.

Members
int Version { get; } The current schema version; increment it whenever the entry's stored shape changes.
void Migrate(int fromVersion) Transforms the entry from an older stored version up to Version. Runs once per upgrade (retried on the next load if it throws, so it must be idempotent); for a per-platform entry, runs on every variant.

ISettingsMigrator

interface

Opt-in to recover data from a settings entry type that was deleted, into surviving types. Discovered implementations are offered every orphaned record when the settings load in the editor, before the record is cleared.

Methods
void OnMissing(MissingSettings missing) Called once per stored record whose type no longer exists. Recognize your own old type by its identity, read it with MissingSettings.TryRead, and write its data into current entries through Settings<T>.Instance and Settings.Save.

MissingSettings

readonly struct

A stored settings record whose declaring type no longer exists, offered to every ISettingsMigrator.

Properties
string ClassName { get; } The class name of the deleted type.
string Namespace { get; } The namespace of the deleted type, or an empty string when it had none.
string AssemblyName { get; } The name of the assembly the deleted type belonged to.
Methods
bool TryRead<TOld>(out TOld value) Deserializes the stored fields of the deleted type into a mirror type you declare (TOld should be a [System.Serializable] type mirroring the deleted type's fields). Returns false when there is no stored data or it cannot be read.
