How CloneBuster proves your work

Understand the vault, the two timestamps, the previews, git, and what a timestamp proves.

A clone can copy a finished game. It can't copy the dated history of how the game was made. CloneBuster keeps that history: a record of every version of your files, each one timestamped by authorities that anyone can check without CloneBuster.

Every version, recorded as you save

CloneBuster watches your Assets folder and any source folders you add, such as the folder that holds your PSD files or your store-page material. When a file changes, CloneBuster waits until it stops changing, then computes its SHA-256 hash, a fingerprint unique to that exact content, and records the hash as a new version.

Versions you save within a few seconds of each other form one batch, and each batch is timestamped once. The first snapshot of the project is a single batch, however many files it holds.

CloneBuster also scans every recorded folder when the Editor starts, after each script compilation, and every few minutes, so a file you change while Unity is closed is recorded too.

Hashing, scanning and timestamping run in the background, so they don't slow the Editor or your saves. Only previews use the Editor's time: it decodes each new image and renders each new model, a few at a time. If large models slow it after each import, turn off Model preview for their format.

Note: Code, scenes, prefabs and data files are recorded like any other file. CloneBuster never shows their contents unless you ask it to.

Two independent timestamps

Each batch is timestamped by two authorities that don't depend on each other:

AuthorityWhat it gives you
An RFC 3161 timestamp authority, FreeTSA by defaultA signed token, issued within seconds, in the standard timestamp format.
OpenTimestampsA proof anchored in the Bitcoin blockchain, usually a few hours later. No wallet, fee or cryptocurrency is involved: public servers called calendars collect hashes and write one transaction for all of them.

CloneBuster lists a batch's hashes in a text file, its manifest, and both authorities receive only the hash of that manifest. They never receive your files, their names, or their individual hashes.

FreeTSA's certificate is valid until 2040, and the Bitcoin proof never expires.

Previews taken at save time

A hash proves a file existed. A reviewer also needs to see what it looked like. When you save an image or a model, CloneBuster makes a preview of that version at once, at most 1080 pixels on its longer side, and lists the preview's hash on the same manifest line as the file's. The preview is therefore timestamped with the version it shows.

A preview has to be made when you save: once the file changes, that version's image is gone. For the formats CloneBuster reads, refer to Supported formats.

Your originals stay with you

CloneBuster keeps no copies of your files, and an export includes none, only the lines of code you choose to show. For each version, the vault stores only its preview, the hashes of the file and of the preview, and the two timestamps that cover both.

If someone asks for a version's exact file, you send it yourself. When you export, CloneBuster warns you about any version you picked that you can no longer produce. It looks for a file whose SHA-256 matches the timestamped hash in two places:

  • The file on disk.
  • The file's last 300 commits in your git history, when the file is tracked.

Code and text files aren't checked. A version found in neither place still exports with its hash, its proofs and its preview.

If you already use git

Git keeps your old files; CloneBuster dates them. A commit's date comes from the committer's machine, rebasing or squashing rewrites it, and a store reviewer can check it only with access to your repository. CloneBuster's dates come from the two authorities, cover every saved version, committed or not, in Assets and the source folders you add, and anyone can check them without your project.

Together, CloneBuster's timestamps date each version, and git holds the exact file of each version you committed. If a dispute reaches court, the records of the host you push to can support the same history.

Purchased assets are never evidence

Another game may have bought the same asset pack as you, so a file you didn't make proves nothing. CloneBuster recognizes the files that come from the Asset Store and never records them:

  • Files whose .meta file carries the AssetOrigin block that Unity 6 writes on import.
  • Files whose GUID appears in a package of your local Asset Store download cache.

For assets from anywhere else, such as stock art or licensed audio, mark their folder as third-party. For more information, refer to Mark a third-party folder. CloneBuster reads all of this on your computer; nothing about your purchases leaves it.

What a timestamp proves

A timestamp proves that a file with this exact content existed by the authority's date. It doesn't prove who made the file, or how. CloneBuster doesn't certify that a work was made without AI, and it doesn't detect copies: you recognize your own work, and CloneBuster gives you the dated evidence for it.

Copyright protects expression, such as art, music, writing, levels and code. It doesn't protect game mechanics, so a clone that copies only how your game plays is outside what any notice can remove.

Hashes and timestamps as evidence

Hashes and timestamps are established forms of digital evidence. For example:

  • United States: Federal Rule of Evidence 902(14) lets a copied file be authenticated by a process of digital identification, which the rule's committee note says is ordinarily a hash value.
  • European Union: eIDAS Article 41 says an electronic timestamp can't be refused as evidence because it's electronic or not qualified. A qualified timestamp is also presumed accurate. FreeTSA, the default, doesn't claim qualified status, so its timestamps are admissible but carry no presumption of accuracy.
  • China: the Supreme People's Court's Online Litigation Rules (Article 16) let a court presume that data preserved in a blockchain hasn't been altered since it was uploaded, unless evidence shows otherwise.
  • India: the Bharatiya Sakshya Adhiniyam, 2023 requires a certificate with each electronic record submitted as evidence, stating its hash value; SHA-256 is one of the listed algorithms.

A court still weighs each piece of evidence. If you're unsure, ask a lawyer who handles copyright.
