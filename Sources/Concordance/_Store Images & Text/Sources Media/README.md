# Sources Media

Sources for the Asset Store marketing images. Every image is an HTML/SVG page here, rendered to PNG with headless Chrome. Edit the HTML or `venn.js`, re-render, never edit a PNG by hand.

| Output (one level up) | Source | Render (Git Bash, from this folder) |
| --- | --- | --- |
| `Cover 1950x1300.png` | `cover.html` | `sh render.sh` |
| `Card 420x280.png` | `card.html` | `sh render.sh card.html "../Card 420x280.png" 420 280` |
| `Social 1200x630.png` | `social.html` | `sh render.sh social.html "../Social 1200x630.png" 1200 630` |
| `Icon 160x160.png` | `icon.html` | `sh render.sh icon.html "../Icon 160x160.png" 160 160` |
| `Assets/Concordance/Editor/Icons/Concordance Mark.png` | `mark.html` | `sh render.sh mark.html "../../Assets/Concordance/Editor/Icons/Concordance Mark.png" 32 32` |
| `Assets/Concordance/Editor/Icons/d_Concordance Mark.png` | `mark.html?dark` | `sh render.sh "mark.html?dark" "../../Assets/Concordance/Editor/Icons/d_Concordance Mark.png" 32 32` |
| `Assets/Concordance/Demo/Art/Mark.png` | `mark.html?demo&size=128` | `sh render.sh "mark.html?demo&size=128" "../../Assets/Concordance/Demo/Art/Mark.png" 128 128` |

`venn.js` generates the three illustrations the pages place with `<image>`. Run `node venn.js` after editing it (it prints each viewBox, the size a page places it at), then re-render:

- `illustration.svg`: the rings with a script file in each, used by the cover (1:1, right half) and the social image (0.73 scale, centred).
- `illustration-card.svg`: the rings without the files, for the card's 840x560 canvas.
- `illustration-icon.svg`: the rings without the files, with thicker lines, for the icon's 320x320 canvas.

The mark, the editor's tab icon, is drawn by hand in `mark.html`, in one grey per skin, without a background; the demo's Modifiers button uses it in gold. The card and the icon are drawn on a canvas twice the output size and rendered at half size. Set `CHROME` if Chrome is not at its default install path.

## Asset Store marketing image rules

From Unity's [What makes a great key image](https://support.unity.com/hc/en-us/articles/210122403-What-makes-a-great-key-image-and-are-there-any-size-restrictions-) (marketing images were previously called key images):

| Image | Size | Allowed text |
| --- | --- | --- |
| Icon | 160x160 (shown at 80x80) | None |
| Card | 420x280 | Asset title, publisher name or logo |
| Cover | 1950x1300 | Asset title, publisher name or logo, a tagline |
| Social media | 1200x630 | None. Unity may skip assets with text on this image for its paid social promotions. |

All images:

- No Unity logo, no sale banners, no watermark, no default Unity skybox, not even as a background.
- Not only a screenshot of the Unity Editor.
- Not blurry, stretched or cropped.
- Each size gets its own design so it stays legible at its display size; never scale the cover down to make the card.
- Keep text minimal: it collides with Store sale overlays and does not localize.
- Screenshots (a separate set) are at least 1200 wide.

The Submission Guidelines add: generative AI is allowed for logos, backgrounds and supplemental visuals when the package's function is accurately reflected (1.6.b); the marketing presentation is reviewed (1.1.a). These images are generated by code, not by generative AI.

## Visual language

- Common ground. Each script is a ring of its own ink; the rings overlap, and the value is the region inside all three, in solid ink: where the scripts agree.
- Background: cream paper, radial from `#fcf9f3` (lighter towards the rings) through `#f4eee3` to `#e6dbc8` at the edges, with a faint brown fractal-noise grain (opacity 0.08 to 0.10).
- Rings: three printing inks, the same on every image and always in the same place: blue `#2f5597` on top, ochre `#c98a1b` bottom left, crimson `#b23a48` bottom right. Each ring is a line in its ink over a light tint of it (opacity 0.15 to 0.18, multiplied, so each pair's overlap shows).
- Value: the triple overlap filled with ink `#221d2b`, under the rings' lines so its edges stay crisp. Nothing inside it.
- Chips (cover and social only): one per script, a `#fbf8f2` file page with its top right corner folded, bordered in its ring's colour, with three abstract code lines and a soft warm shadow, in the part of its ring no other ring covers. No real text inside the illustration, so it stays within the image text rules.
- Text: title in ink `#221d2b`, tagline `#4a4256`. Font: Segoe UI Variable Display, bold title, regular tagline.
- Cover: text on the left, vertically centred, the tagline on two lines; the rings on the right.
- Card: title on top, the rings centred below.
- Social: the cover's illustration alone, centred.
- Icon: the rings and the value only, with thicker lines. No chips: they blur at 80x80.
- Mark: the icon's rings as lines and the value as the only fill, in one grey per skin (Editor Foundations' `#555555` light, `#c4c4c4` dark), on the 32 px grid shown at 16. The rings sit further apart than on the icon, so the gaps between them stay open at 16 px; closer rings blur into one blob.
- Rejected:
  - Sheet music, the scripts as wavy strands of their own pitch landing on a note head over a staff: the note is the usual symbol for audio, and on the card and icon, which carry no tagline, the package read as an audio tool.
  - Strands running from the scripts into an inspector field: any shape with lines trailing behind it reads as a creature with tails (a squid, a tampon), and an arrow between strands and field to break that reads as a patch, unexplained. As alternatives, the three inks layered inside the field read as a battery, a braid as DNA, strands dropping into the field from above as a router.
  - Stacked layer cards or plates (credit cards, or the generic layers icon) and three nested arcs drawing a C (a target or a signal): none says what the package does as directly as the rings' common ground.
  - A value bar inside the triple overlap: it reads as a minus sign.
  - The documentation's dark theme with its pastel accents and a glowing value, which gave the images no identity of their own. A fourth ink (teal) on the cover and social only: the images must share one set of inks, and four crowd the icon.

## Wording

- Store title (design): `Concordance - Coordinate Scripts Sharing Values`. Images show `Concordance` only; the card shows nothing else. Rejected: `Concordance: Coordinate Every Value` (Concordance coordinates the scripts, not the values; the colon is also off-norm for store titles), and any second half as a cover subtitle, since the tagline already says it.
- Tagline (cover only, under the title): `Coordinate the scripts that write the same value.`, the Quick Usage Guide's tagline.
- No publisher name.
- Description opening: one sentence naming the problem and the scope (every field or property, the user's own and Unity's). Rejected: a second paragraph comparing Concordance to Unity's per-domain solutions (Volumes, Cinemachine priorities, Animator layers, mixer snapshots), which a newcomer has not met yet; the bug section below explains the problem with everyday cases instead.
- Description vocabulary: words a buyer understands without the docs (a change, a regular assignment, a field or property), never the package's own terms (modifier, base value, plain write, member, phase). No code examples: the description says what code changes in programming words (an assignment marked with one keyword). Tags may use search terms such as "modifiers".
- Rejected: a Questions section (do I need to code, does it change my source files, what about packages and DLLs), as Unity's SEO guide advises: every answer repeated another section, and the whole read as defensive. The one fact found nowhere else, writes from packages and DLLs, is an Under the Hood bullet.
- AI-assisted coding: a description section, "Ready for AI-Assisted Coding", and screenshot 04. It opens by saying Concordance needs no AI, then lists what helps when an assistant writes scripts, without promising to fix generated code. Rejected: a passing mention only (most scripts are now written with an assistant, so buyers look for it), and claims that it catches where generated code breaks most.
