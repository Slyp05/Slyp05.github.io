Troubleshooting

Find out what changed a value, and fix common issues with Concordance.

Find out what changed a value

To find out why a member has its value, open it in the Concordance window, and watch it. In Play mode, its Values section shows each modifier and the value it gives, and its History section shows each change with the line that made it.

Messages in the Console window

Concordance cannot process modifier lines

The Console window displays Concordance cannot process modifier lines, and modifier lines throw when they run. Concordance's build step needs the Mono Cecil package (com.unity.nuget.mono-cecil) 1.10 or later: the package is missing or too old, or the build step failed to compile.

To fix it, install or update the Mono Cecil package in the Package Manager window, as the message says. If the package is up to date, look for the build step's compile error in the Console window.

Concordance cannot read ConcordanceSettings.asset

The Console window displays Concordance cannot read 'ProjectSettings/ConcordanceSettings.asset'. The file is damaged, such as by a merge conflict. Until you fix it, every script applies in its phase in code, and the order is read-only.

To fix it, restore the file from version control, then reopen the project. To start over with no order set, delete the file instead.

Exceptions

A line was not rewritten when it compiled

A modifier line, or a call such as Modify or Observe, throws was not rewritten when its assembly compiled. The code was compiled outside Unity, such as by a hot reload tool.

To fix it, let Unity recompile the assembly.

Concordance works only in Play mode or while a test runs

A call throws Concordance works only in Play mode or while a test runs. The line ran in Edit mode, such as from OnValidate, where a value with its modifiers would be saved into the scene or the asset.

To fix it, run the line in Play mode only.

Concordance can only be used from the main thread

A call throws can only be used from the main thread. A thread other than the main thread wrote a modifier, or wrote a member of an object that has modifiers or observers.

To fix it, write modifiers, and the members they modify, from the main thread.

Unexpected values

A modifier's effect stays after it stops

A plain write computed from the member, such as x *= 2f, read the value with its modifiers, so the modifiers ended up in the base value.

To fix it, compute the write from x.GetUnmodified(). For more information, refer to Read the base value.

A modifier lasts after the script that wrote it is gone

The modifier's owner is still alive. For a line in a static method, the owner is the class, which is never destroyed.

To fix it, stop the modifier yourself, or pass an owner. For more information, refer to When a modifier ends.

A modifier has no effect, or two apply in the wrong order

A later modifier may replace the value this one gives. To check, read the member's Values section in the Concordance window in Play mode.

To fix it, set a phase in code, or drag the scripts in the member's Modifier Order. For more information, refer to Order modifiers.

Modifiers stop applying after a plugin writes the member

The plugin's write is untracked: it comes from code Concordance doesn't rewrite, and replaces the value without the modifiers until the member's value is next computed.

To fix it, call Recombine() on the member after the plugin's write. For more information, refer to Untracked writes.
