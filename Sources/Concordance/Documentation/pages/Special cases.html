Special cases

Understand how Concordance handles animation and physics, and declare your own special cases.

A special case is a member Concordance handles differently from other fields and properties:

  • A driven member, written at known moments of each frame by code Concordance doesn't rewrite, such as animation.
  • An unmodifiable member, which takes no modifiers.
  • A getter and setter method pair that forms one member.

Animated members

Animation writes the members it animates from engine code, which Concordance doesn't rewrite. Concordance knows these members: right after each animation stage of the frame, the value the animation wrote becomes the base value, and the modifiers apply on top. A member written this way is a driven member. Concordance checks one only while it has modifiers or observers, or while you watch it in the Concordance window, whose History then shows what the animation wrote.

The built-in driven members are every member an animation clip can write on a built-in component, and the values of Unity UI controls. For a clip that animates a field of your own script, declare the field as a driven member, as described in Declare your own special cases.

Members the engine updates

The engine computes some members from their own previous value, such as a velocity the physics engine updates each step. A modifier on one would compound at every step, so a modifier line on it is a compile error that names what to modify instead: a force, gravityScale, an agent's speed, or a playback pitch.

These unmodifiable members are the velocities, positions, rotations and forces of rigidbodies and articulation bodies, a nav mesh agent's velocity and position, playback times, and the text and scroll position of Unity UI fields and scroll rects. Observing them works.

Declare your own special cases

The built-in special cases are declared with assembly attributes from Concordance.Advanced. Use the same attributes for your own members or a package's:

using Concordance.Advanced;
using UnityEngine.PlayerLoop;

[assembly: UnmodifiableMember(typeof(CharacterMotor), nameof(CharacterMotor.Velocity), Instead = "CharacterMotor.MaxSpeed")]
[assembly: DrivenMember(typeof(AudioSource), nameof(AudioSource.volume), typeof(Update))]
AttributeEffect
UnmodifiableMemberMakes a modifier line on the member a compile error. Instead names what to modify instead.
DrivenMemberRight after each player-loop stage you name, the value written during that stage becomes the base value.
PropertyMethodsMakes a getter and setter method pair one member.

A declaration applies to its assembly and to the assemblies that reference it. For a type your build may not include, such as one from an optional package, name the type by its assembly-qualified name and the member by string, as in "UnityEngine.Cloth, UnityEngine.ClothModule".

Declare your own getter and setter pair

A getter and setter pair is two methods that read and write one value, such as Transform.GetSiblingIndex and Transform.SetSiblingIndex. Concordance treats each of Unity's pairs as one member, so a modifier line passes (Modifier) to the setter, as described in Getter and setter methods. To make a pair of your own methods one member, declare it with [assembly: PropertyMethods]:

using Concordance.Advanced;
using UnityEngine;

[assembly: PropertyMethods(typeof(Thermostat), getter: nameof(Thermostat.GetTarget), setter: nameof(Thermostat.SetTarget))]

public class Thermostat : MonoBehaviour
{
    float target = 20f;

    public float GetTarget() => target;
    public void SetTarget(float value) => target = value;
}

The setter takes the value as its only parameter, and the getter takes none. A pair whose methods take a key, such as a room name, is not a member: wrap it in a property, as described in Wrap a value in a property.

Find a member's special case

To find out whether a member is a special case, select it in the Concordance window. Under its name, its details say what makes it a special case, and the tooltip of that line names where the special case is declared.
